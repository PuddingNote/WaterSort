# GameDesign — WaterSort (색깔 정렬 퍼즐)

> 원본 기획서: `색깔정렬게임_기획서_범용형.md`(소재 무관 공통 로직) +
> `색깔정렬게임_기획서_물병버전.md`(물병 테마 특화). 이 문서는 그 둘을 이
> 프로젝트 기준으로 합쳐 정리한 요약이다. **기획서 문구와 실제로 구현하며
> 확정한 규칙이 달라지면, 기획서를 고치는 대신 이 문서에 "왜 다르게
> 확정했는지"를 추가해 나간다** (재사용 노트 9장 원칙).

## 한 줄 컨셉
여러 병에 뒤섞여 담긴 색깔 물을 병 사이로 부어 옮겨, 한 병에 한 가지 색만
남으면 클리어되는 캐주얼 퍼즐 (Water Sort Puzzle류).

## 핵심 로직 (소재 무관 — Core/Solver에 구현될 것)
- 이동 조건: 출발 병에 물 1칸 이상, 도착 병에 여유 슬롯 1칸 이상, 도착 병이
  비어있거나 최상단 색이 출발 병 최상단 색과 동일.
- 이동량: 출발 병 최상단부터 연속된 동일 색을, 도착 병 여유 슬롯이 허용하는
  만큼만 이동.
- 클리어: 사용 중인 모든 병이 "완전히 비어있음" 또는 "한 색으로 가득 참" 중 하나.
- 실패(게임오버) 조건 없음 — 교착 상태만 감지해 힌트/초기화/병 추가로 유도.
- 라운드 생성은 **역방향(Reverse) 생성 방식**: 이미 클리어된 상태에서 역연산을
  M회(`shuffleDepth`) 반복해 섞는다 → 생성 즉시 클리어 가능함이 보장됨. 사후
  "풀리는지 검증" 방식은 채택하지 않는다(비용 大, 재생성 반복 위험).
- 난이도는 병 개수 하나로 판단하지 않는다. `slotCount`, `colorCount`,
  `emptyContainerCount`(가장 큰 음의 가중치), `shuffleDepth`, `colorSpread`가
  함께 작용 — 병 개수가 적어도 다른 변수로 충분히 어려워질 수 있다.
  `DifficultyScore` 산식과 라운드 구간별 파라미터 표는 범용형 기획서 6.4~6.5
  그대로 참고(실제 가중치는 플레이테스트로 튜닝 필요 — 아직 미확정).

## 물병 테마 특화 (Presentation — UI 계층 안에 위치)
- 배치: 최대 2줄 × 줄당 6개 = 최대 12병. 슬롯 수는 라운드당 4~9칸(라운드 내
  전체 병이 동일 슬롯 수).
- 색상 팔레트 9종 고정(레드/그린/블루/옐로우/핑크/퍼플/그레이/스카이블루/
  스카이그린). 라운드는 이 중 일부만 사용.
- 붓기(Tilt) 애니메이션, 도착 병 실시간 차오름, 여러 층 동시 이동은 하나의
  흐름으로, 무효 이동 시 살짝 기울었다 복귀 + 진동.
- 색맹 접근성: 유사 색상 쌍(블루/스카이블루, 그린/스카이그린) 명도·채도 차이
  확보 + 패턴 표시 옵션 (범용형 문서에도 공통 적용 가능하다고 명시돼 있음 —
  다음 테마 이식 시에도 유지할 것).

## 필수 기능 (공통 정책, 소재 무관 로직 + 물 연출)
| 기능 | 정책 |
|---|---|
| 초기화(Reset) | 라운드 시작 상태로 즉시 복원, 이동/undo 이력 초기화. 확인 팝업 권장 |
| 실행취소(Undo) | 스택 기반, 라운드 시작 지점까지 연속 가능. 물 버전은 붓기 역재생 연출 |
| 힌트 | 무료 2회, 5라운드 클리어마다 1회 충전, 이후 보상형 광고 1회 = 1회 사용. 솔버가 최적 다음 수 계산 후 자동 실행 |
| 병 추가 | 광고 1회 = 병 총 슬롯의 20%씩 순차 생성(완성 전 사용 가능 여부는 TBD). 매 라운드 시작 시 사용 횟수 초기화 |
| 라운드 전면광고 | 3라운드 클리어마다 1회, 닫으면 자동 다음 라운드 |

## UI 배치 (게임 화면)
좌상단 뒤로가기 · 우상단 설정 · 중앙 병 배치 영역 · 좌하단 실행취소+초기화 ·
우하단 힌트+병추가. 타이틀 화면은 중앙 상단 로고 + 시작 버튼 위 부제 + 좌상단
설정 + 시작/종료 버튼.

## 데이터 구조 (참고용 — 실제 필드명은 구현 시 확정)
```json
{
  "roundId": 45,
  "difficultyScore": 62,
  "bottleSlotCount": 6,
  "colorCount": 5,
  "emptyBottleCount": 2,
  "bottles": [
    { "id": 0, "waterLayers": ["yellow", "skyblue", "green"] }
  ]
}
```
`waterLayers` 마지막 값이 병 입구(최상단, 이동 가능한 물).

## 확정이 필요한 정책 (기획서 8장/9장 To-Do — 아직 결정 안 됨)
- [ ] 힌트 잔여 개수 최대 보유 한도(캡)
- [ ] 병 추가로 생긴 "부분 완성 병"의 사용 가능 시점 (완성 전 이동 가능 여부)
- [ ] 병 추가 20% 정책의 슬롯 수 기준 (4칸 vs 5칸 설계 — `slotCount`가 라운드마다
      달라지므로 상대적 비율 계산 방식 확정 필요, 권장안: 5칸 기준 슬롯 단위 부여)
- [ ] 뒤로가기 시 진행 상태 저장(이어하기) 여부
- [ ] 실행취소와 병 추가의 상호작용(병 추가도 되돌릴 수 있는지)
- [ ] 광고 미시청/로드 실패 시 대체 처리(힌트/병추가 비활성 vs 재화 대체 지급)
- [ ] `DifficultyScore` 가중치·난이도 곡선 계수의 최종 값 (자기대전으로
      "우상향은 하더라" 정도는 확인됨 — `docs/Architecture.md` 참고. 사람이
      실제로 체감하는 난이도에 맞춘 최종 튜닝은 사람 플레이테스트로 확정 필요)
- [ ] 붓기 애니메이션 소요 시간 및 스킵(연타 방지) 가능 여부
- [ ] 여러 층 동시 부을 때 사운드(단일 vs 층별)
- [ ] 색맹 접근성 패턴 표시 옵션 도입 여부
- [ ] 슬롯 수(4~9) 가변 시 병의 화면상 세로 길이 처리 (스크롤 없이 수용 가능한
      최대 슬롯 수 검증)

이 목록은 실제로 그 기능을 구현하는 시점에 사용자에게 확인하고, 결정되는
대로 이 문서에서 지우고 위 표/규칙 쪽에 반영한다(재사용 노트 9장: "예외/edge
case는 지금 결정하지 않고 필요한 시점에 사용자에게 묻는다").
